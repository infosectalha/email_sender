# Agent Instructions for Smart Email Outreach & Client Manager Tool

This document provides guidance for AI agents maintaining or developing this Smart Email Outreach & Client Manager tool. The tool has evolved from a simple PDF report generator to a more comprehensive outreach assistant.

## Project Structure

The project consists of several Python modules:

-   **`main.py`**:
    -   The entry point of the application.
    -   Handles the Tkinter GUI, user interactions for campaign management, template selection, CSV import, email preview, and sending.
    -   Coordinates calls to other manager modules (`TemplateManager`, `CRMManager`, `EmailSender`, `PDFGenerator`).
-   **`template_manager.py`**:
    -   Manages Jinja2 email templates located in the `templates/` directory.
    -   Loads templates and renders them with dynamic context data.
    -   Makes the standard HTML signature globally available to templates.
-   **`crm_manager.py`**:
    -   Manages client data and interactions using an SQLite database (`clients.db`).
    -   Handles adding/updating clients, logging email interactions, and provides methods to retrieve client data.
    -   Defines `clients` and `interactions` tables.
-   **`signature_handler.py`**:
    -   Stores and provides the standard HTML email signature.
    -   (Currently, its `append_signature_to_html` is less used as signature is injected via Jinja2 global context in `TemplateManager`).
-   **`email_sender.py`**:
    -   Handles the actual sending of emails via Gmail's SMTP server using `smtplib` and `ssl` (STARTTLS).
    -   Constructs MIME messages and handles attachments. Expects HTML body content.
-   **`pdf_generator.py`**:
    -   Responsible for creating basic PDF reports using `fpdf2`.
    -   Receives data (typically from CSV via `main.py`) to populate the PDF.
    -   Generated reports are saved in the `generated_reports/` directory.
-   **`templates/` (Directory)**: Contains user-editable HTML email templates using Jinja2 syntax.
-   **`generated_reports/` (Directory)**: Default output directory for PDFs generated by the tool on-the-fly during campaigns.
-   **`README.md`**: User-facing documentation.
-   **`AGENTS.md`**: This file.
-   **`clients.db` (SQLite file)**: Created at runtime to store CRM data.

## Key Libraries and Choices

-   **Tkinter (GUI):** Retained for its standard library status, suitable for the tool's functional UI needs.
-   **Jinja2 (Templating):** Chosen for powerful and flexible HTML email templating, as requested.
-   **SQLite3 (CRM):** Standard library choice for robust local database storage for client tracking.
-   **fpdf2 (PDF Generation):** Retained for pure Python PDF generation.
-   **smtplib, ssl (Email Sending):** Standard libraries for SMTP.
-   **csv (CSV Parsing):** Standard library for reading campaign data from CSV files.

## Development Principles Followed

-   **Modularity:** Clear separation of concerns (GUI, templating, CRM, email sending, PDF generation).
-   **Campaign-Centric Workflow:** The UI and logic are now primarily designed around managing email campaigns from CSV data.
-   **Data-Driven Content:** Emails and PDFs are dynamically generated based on data from CSV files and selected templates.
-   **User Configuration:** Relies on user input for Gmail credentials (not stored) and CSV files for campaign data.
-   **Error Handling:** try-except blocks are used for file operations, network communication, database interactions, and template rendering. Feedback is provided via UI status bar and dialogs.
-   **Extensibility (Basic):** Adding new email templates is a matter of creating new HTML files in the `templates/` directory. The CSV format is flexible in accepting additional columns for template context.

## Potential Future Enhancements & Considerations

-   **Advanced CRM UI:**
    -   A dedicated UI section/tab to browse, search, edit, and manually add clients in the CRM.
    -   Display interaction history for a selected client.
    -   Implement follow-up reminders (flag clients not replied in X days).
-   **Advanced PDF Generation:**
    -   More UI controls for customizing PDF content or selecting different PDF templates.
    -   Integration with other tools or more sophisticated data parsing for richer PDF reports.
-   **Email Preview Robustness:**
    -   Consider using a dedicated HTML rendering widget for more accurate email previews if complex HTML/CSS is used in templates (though Tkinter's Text widget is generally sufficient for basic HTML).
-   **Configuration File:**
    -   Store user's Gmail address (but **never** App Password), sender name, or default template preferences in a config file (e.g., JSON, INI).
-   **Background Processing for Campaigns:** For very large campaigns, implement email sending in a separate thread or using asyncio to prevent GUI freezes and allow for cancellation.
-   **Rate Limiting Awareness:** Be mindful of Gmail's sending limits. The current small delay between sends is a basic measure. More sophisticated handling might be needed for high volumes.
-   **Advanced Template Logic:**
    -   Allow templates to specify their own subject lines (e.g., via frontmatter in the template file or a naming convention).
    -   More complex conditional logic within templates based on CRM data.
-   **OAuth2 for Gmail:** For a more user-friendly authentication (though more complex to implement), consider OAuth2 instead of App Passwords, if the tool were to be distributed more widely or as a web service component. For a local desktop tool, App Passwords are a reasonable compromise.
-   **Contact List Management:** Features to manage multiple contact lists or segment clients more effectively within the CRM.
-   **A/B Testing for Templates:** UI and logic to support sending different template variations to segments of a list.
-   **Rating Integration (Optional):** As per the original extended request, adding a 5-star rating link/image in emails. This would likely require an external service/endpoint to receive and store ratings.
-   **Packaging:** Use PyInstaller or cx_Freeze for easier distribution.

## Maintaining Code Quality

-   **Modularity:** Continue to keep concerns separated in their respective modules.
-   **Readability:** Maintain clear code, comments, and consistent naming.
-   **Error Handling:** Ensure new features include appropriate error handling and user feedback.
-   **Security:** Always prioritize security, especially around credentials (current model of not storing App Passwords is good) and data handling.
-   **Testing:** Add unit tests for business logic in managers (CRM, template) and functional tests for UI workflows if possible.

This guidance should help in understanding the current state of the project and making informed decisions for future development.
